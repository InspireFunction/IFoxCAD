# 工作流程与协作机制
> 详细描述多智能体协作系统的标准工作流程

## 1. 标准三层协作流程

### 1.1 任务接收与分析阶段
```
用户请求
    │
    ▼
妈妈(秘书长)接收需求
    │
    ├─→ 需求理解与分析
    │     ├─→ 提取关键信息
    │     ├─→ 识别任务类型
    │     └─→ 评估复杂度
    │
    └─→ 任务登记与分配
          ├─→ 生成任务ID
          ├─→ 创建任务分支
          └─→ 确定处理策略
```

### 1.2 任务分类处理策略

#### 简单直接任务 (快速通道)
- **识别标准**: 单一功能、明确需求、无复杂依赖
- **处理流程**: 妈妈直接分配给对应执行层的xx君
- **典型场景**: 
  - "写个函数计算矩形面积" → 码农君
  - "加个单元测试" → 测试君  
  - "格式化这段代码" → 美化君

#### 复杂管理任务 (专业通道)
- **识别标准**: 多任务协调、冲突检测、性能优化、批量处理
- **处理流程**: 妈妈转交给项目管理层专业处理
- **典型场景**:
  - "检测任务冲突并优化" → 项目经理君
  - "总结经验形成知识库" → 知识君

### 1.3 执行与监控阶段

#### 简单任务执行流程
```
执行层君接收任务
    │
    ├─→ 任务理解与准备
    │     ├─→ 查看现有代码
    │     ├─→ 理解业务逻辑
    │     └─→ 制定实施方案
    │
    ├─→ 具体执行实施
    │     ├─→ 编写/修改代码
    │     ├─→ 自测验证
    │     └─→ 代码整理优化
    │
    └─→ 结果提交与汇报
          ├─→ 更新任务状态
          ├─→ 提交代码到分支
          └─→ 向妈妈汇报完成
```

#### 复杂任务执行流程
```
项目管理层接收任务
    │
    ├─→ 任务分析与规划
    │     ├─→ 冲突检测分析
    │     ├─→ 依赖关系梳理
    │     ├─→ 执行计划制定
    │     └─→ 资源分配优化
    │
    ├─→ 任务分解与分配
    │     ├─→ 拆分子任务
    │     ├─→ 确定执行顺序
    │     ├─→ 分配给执行层
    │     └─→ 设置监控点
    │
    ├─→ 并行执行与监控
    │     ├─→ 实时进度跟踪
    │     ├─→ 异常情况处理
    │     ├─→ 性能数据采集
    │     └─→ 动态调整优化
    │
    └─→ 结果汇总与分析
          ├─→ 收集执行结果
          ├─→ 生成分析报告
          ├─→ 提出优化建议
          └─→ 向妈妈汇报总结
```

## 2. 任务状态流转机制

### 2.1 状态定义与转换
```
pending(待开始) 
    │ 妈妈分配任务
    ▼
doing(进行中) 
    │ 步骤完成
    ▼
done(已完成) 
    │ 发生错误
    ▼
error(出错) → rollback(回滚) → doing(重新进行)
```

### 2.2 状态更新责任
- **妈妈**: 负责状态初始化和最终确认
- **项目管理层**: 负责复杂任务的状态跟踪
- **执行层**: 负责具体步骤的状态更新

### 2.3 状态记录要求
- 所有状态变更必须记录在 `task-state.md`
- 包含变更时间、责任人、变更原因
- 异常情况必须详细记录错误信息和处理方案

## 3. 协作沟通机制

### 3.1 层级间沟通规范

#### 上行沟通 (执行层→项目管理层→妈妈)
```
执行层遇到问题
    │
    ├─→ 问题分析与定位
    ├─→ 尝试自主解决
    └─→ 上报项目管理层
          │
          ├─→ 项目管理层分析
          ├─→ 制定解决方案
          └─→ 上报妈妈决策
                │
                ├─→ 妈妈评估决策
                ├─→ 确定处理策略
                └─→ 对外沟通协调
```

#### 下行沟通 (妈妈→项目管理层→执行层)
```
妈妈接收用户需求
    │
    ├─→ 任务分析与分类
    ├─→ 确定处理层级
    └─→ 分配任务
          │
          ├─→ 项目管理层接收
          │     ├─→ 任务理解与分析
          │     ├─→ 制定执行计划
          │     └─→ 分解子任务
          │
          └─→ 执行层接收
                ├─→ 具体任务理解
                ├─→ 制定实施方案
                └─→ 执行并反馈
```

### 3.2 横向协作机制

#### 项目管理层内协作
- **项目经理君**: 负责技术方案协调、资源冲突解决
- **知识君**: 提供知识支持和经验参考

#### 执行层内协作
- **码农君**: 功能开发完成后通知测试君
- **测试君**: 测试完成后通知文档君更新文档
- **修Bug君**: 修复完成后通知相关xx君验证
- **美化君**: 代码整理完成后统一提交

## 4. 异常处理流程

### 4.1 异常分类与处理级别

#### 执行层异常 (低级异常)
- **编译错误**: 修Bug君处理,码农君协助
- **逻辑错误**: 码农君重新分析,测试君验证
- **格式问题**: 美化君处理,无需上报

#### 项目管理层异常 (中级异常)
- **任务冲突**: 项目经理君分析,提出解决方案
- **资源不足**: 项目经理君调整计划,优化资源分配
- **知识缺失**: 知识君补充知识,提供参考方案

#### 系统性异常 (高级异常)
- **多任务失败**: 妈妈评估是否整体回滚
- **架构问题**: 妈妈组织协调各层重新设计
- **用户不满**: 妈妈直接沟通协调处理

### 4.2 异常上报机制
```
异常发生
    │
    ├─→ 立即记录异常信息
    │     ├─→ 异常时间
    │     ├─→ 异常现象
    │     ├─→ 影响范围
    │     └─→ 初步分析
    │
    ├─→ 评估异常级别
    │     ├─→ 低级: 本层处理
    │     ├─→ 中级: 上报项目管理层
    │     └─→ 高级: 上报妈妈
    │
    └─→ 跟踪处理进度
          ├─→ 记录处理方案
          ├─→ 验证处理结果
          └─→ 总结经验教训
```

## 5. 质量保证机制

### 5.1 质量检查点
- **任务开始前**: 需求理解确认
- **执行过程中**: 关键步骤验证
- **任务完成后**: 结果质量检查
- **交付给用户前**: 最终质量确认

### 5.2 质量责任链
- **执行层**: 保证具体实现质量
- **项目管理层**: 保证整体方案质量
- **妈妈**: 保证最终交付质量

### 5.3 质量改进循环
```
质量检查 → 问题发现 → 原因分析 → 方案制定 → 实施改进 → 效果验证 → 经验总结
```

## 6. 效率优化机制

### 6.1 并行执行优化
- **无依赖任务**: 并行执行,最大化效率
- **资源充足**: 多君同时工作
- **智能调度**: 动态调整执行顺序

### 6.2 资源利用优化
- **技能匹配**: 任务分配给最适合的君
- **负载均衡**: 避免单个君过载
- **经验复用**: 优先使用已有知识和经验

### 6.3 持续改进机制
- **执行时间统计**: 分析各君效率
- **成功率监控**: 识别改进空间
- **用户反馈收集**: 优化协作流程

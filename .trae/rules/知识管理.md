# 知识管理与技能规范
> 错误记录、成功经验记录和技能管理的详细规范

## 1. 错误记录规范

### 1.1 错误记录触发条件
当遇到以下情况时必须创建错误记录:
- 编译失败且找到解决方案
- 运行时异常且成功修复
- 逻辑错误且分析出根本原因
- 环境配置问题且解决
- 第三方库使用问题且找到正确方法

### 1.2 错误记录文件规范

#### 文件命名
```
错误-{简短描述}.md
示例: 错误-编译器版本不匹配.md
     错误-LINQ查询性能优化失败.md
     错误-CAD接口调用异常.md
```

#### 文件位置
`#.trae\skills\错误-{描述}.md`

#### 内容结构
```markdown
---
trigger: 触发关键词,场景描述
category: 错误记录
tags: [标签1, 标签2, 标签3]
---

# 错误-{标题}

## 错误现象描述
详细描述遇到的错误现象,包括:
- 错误发生时的操作步骤
- 具体的错误信息和异常堆栈
- 错误发生的上下文环境
- 错误的影响范围

## 错误原因分析
深入分析错误产生的根本原因:
- 技术层面的原因分析
- 环境或配置相关的原因
- 代码逻辑层面的问题
- 第三方依赖相关的原因

## 解决方案步骤
详细说明解决错误的具体步骤:
1. 第一步操作
2. 第二步操作
3. 验证修复效果
4. 相关代码修改

## 预防措施
为避免类似错误再次发生,提出预防措施:
- 代码层面的预防措施
- 流程层面的改进建议
- 环境配置的注意事项
- 团队协作的改进点

## 相关资源
- 相关文档链接
- 参考解决方案
- 类似错误案例
```

## 2. 成功经验记录规范

### 2.1 成功经验触发条件
当出现以下情况时应该创建成功经验记录:
- 成功解决复杂技术问题
- 发现高效的代码优化技巧
- 总结出可复用的设计模式
- 找到性能瓶颈的优化方案
- 形成有效的调试方法

### 2.2 成功经验文件规范

#### 文件命名
```
经验-{简短描述}.md
示例: 经验-高效LINQ优化技巧.md
     经验-CAD图形处理最佳实践.md
     经验-多线程并发调试技巧.md
```

#### 内容结构
```markdown
---
trigger: 触发关键词,应用场景
category: 成功经验
tags: [标签1, 标签2, 标签3]
applicability: 适用条件描述
---

# 经验-{标题}

## 场景描述
详细描述应用此经验的具体场景:
- 业务背景和需求
- 技术挑战和约束条件
- 预期的目标和效果
- 相关的上下文信息

## 解决方案
详细说明具体的解决方案:
### 核心思路
- 解决问题的整体思路
- 采用的关键技术和方法
- 方案的优势和特点

### 实现步骤
1. 环境准备和前置条件
2. 核心实现步骤
3. 关键配置和参数
4. 验证和测试方法

## 代码示例
提供完整的代码示例:
```csharp
// 核心代码实现
public class Example
{
    // 关键方法实现
}
```

## 性能数据
提供性能对比数据(如果有):
- 优化前后的性能对比
- 资源消耗的变化情况
- 可扩展性评估

## 适用条件
明确说明此经验的适用条件:
- 技术环境要求
- 业务场景适用性
- 性能要求约束
- 不适用的情况说明

## 扩展思考
- 此经验的变种和扩展
- 相关技术的结合应用
- 未来可能的优化方向
```

## 3. Skill文件管理规范

### 3.1 Skill分类体系

#### 按类型分类
- **错误记录**: 问题解决方案
- **成功经验**: 最佳实践总结
- **技术技巧**: 具体技术实现
- **工具使用**: 开发工具使用技巧
- **流程优化**: 工作流程改进

#### 按技术领域分类
- **CAD开发**: AutoCAD二次开发相关
- **.NET技术**: .NET Framework相关
- **数据库**: 数据访问和存储
- **前端技术**: 界面和交互相关
- **性能优化**: 性能调优相关

### 3.2 Skill标签规范

#### 技术标签
```
# 编程语言
csharp, dotnet, linq

# 技术框架  
wpf, winforms, aspnet

# CAD相关
autocad, cad-api, dllimport

# 数据库
sql, entity-framework, dapper

# 工具工具
visual-studio, git, resharper
```

#### 场景标签
```
# 开发阶段
development, debugging, testing

# 性能相关
performance, optimization, memory

# 架构设计
architecture, design-pattern, refactoring

# 问题类型
bug-fix, error-handling, exception
```

### 3.3 Skill使用规范

#### 触发条件设置
- **精确匹配**: 使用具体技术名词
- **场景匹配**: 使用应用场景描述
- **问题匹配**: 使用问题现象关键词

#### 内容质量要求
- **准确性**: 确保技术内容的准确性
- **完整性**: 提供完整的解决方案
- **可读性**: 结构清晰,易于理解
- **可复用**: 提供可直接使用的代码

### 3.4 Skill维护更新

#### 定期审查
- 每月检查Skill的适用性
- 更新过时的技术内容
- 补充新的使用案例

#### 版本管理
- 重大更新时保留历史版本
- 记录更新内容和原因
- 维护Skill之间的关联关系

#### 知识整合
- 合并相似的Skill内容
- 建立Skill之间的引用关系
- 形成知识体系网络

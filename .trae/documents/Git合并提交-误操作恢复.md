# Git 合并提交的误操作总结

## 问题场景

不小心 `git reset` 到旧历史（已经 push 的提交），此时推送不上去。
也就是合并了git commit多条信息.

## 核心原则

⚠️ **禁止 `git push -f`** - 强制推送会覆盖远程历史，危险操作！
⚠️ **有撤回历史的安全合并,可以回滚到合并前的状态**

## 解决步骤

### 第一步：本地提交备份

```bash
git commit -m "backup: 原分支名_本地备份_{序号}"
```

**说明：** 必须先本地提交一次，才能用 `git reflog` 回滚，避免文件丢失。

### 第二步：创建备份分支

例子:
把jing分支的状态备份到jing2分支
```bash
git branch jing2
```

**说明：** 保存当前状态到 jing2 分支。

### 第三步：查找共同历史

```bash
git lg
```

**说明：** 找到远程分支和本地都有的一个旧历史，例如：`35e22c8`

### 第四步：回滚到旧历史

```bash
git reset 35e22c8
```

**说明：** 回滚到共同历史，此时会出现一些文件差异，不用管。

### 第五步：拉取远程最新

```bash
git pull
```

**说明：** 此时本地和远程一致了。

### 第六步：合并备份分支

```bash
git merge -X theirs jing2 -m "merge: 合并 jing2 分支，以 jing2 版本为准"
```

**说明：** 使用 `-X theirs` 策略，以 jing2 版本为准解决冲突，不需要处理差异。

## 结果

```
* xxxxxxx (HEAD -> jing) merge: 合并 jing2 分支，以 jing2 版本为准
*|\
| * xxxxxxx (jing2) backup: 本地备份
* | xxxxxxx (origin/jing) 远程最新提交
|/
* 35e22c8 共同历史点
```

**效果：**
- ✅ 没有使用 `git push -f`
- ✅ 保留了所有改动
- ✅ 可以正常推送
- ❌ 历史会多一个合并提交（这是不用强制推送的代价）

## 消除合并分支，只留下一个

**适用情况：** 合并操作还在本地，未推送到远程仓库，想要简洁的直线历史

### 操作步骤

```bash
# 第一步：软重置到合并前的状态（保留所有改动）
git reset --soft <远程最新提交的commit>

# 第二步：修复代码格式问题（项目自定义命令）
git ec-fix

# 第三步：重新提交为一个提交
git add .
git commit -m "添加根路径配置"
```

### 最终状态

```
* 9330733d (HEAD -> jing) 添加根路径配置   ← 新的单一提交（直线历史）
* a5b0dc25 (origin/jing) 添加抑制规则
* fd71e16e Directory.Build定义根路径
```

**效果：**
- ✅ 两个分支的改动合并完成
- ✅ 历史变成一条直线，没有分叉
- ✅ 可以正常 `git push` 推送
